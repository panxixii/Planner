## 项目简介

Planner 是一个面向个人长期目标与复杂任务管理的毕业设计项目。它不只是传统任务清单或文件夹式项目管理工具，而是以“全局任务引用”为数据基础，通过树形结构和可视化有向图表达任务的层级与依赖，再结合增强型甘特、Todo 执行路线、草稿画布和周期时间模板，形成从目标拆解、关系梳理到时间执行的完整规划流程。

项目采用纯前端架构，数据默认保存在当前浏览器本地，无需注册或登录即可使用。

> 在线地址：**https://panxixii.github.io/Planner/**

## 核心创新

### 1. 节点是真正的全局引用，而不是简单复制

市面上许多规划工具在不同页面、项目或视图中复用任务时，本质上是在复制一份数据，容易产生内容不同步、状态不一致和重复维护的问题。

Planner 将任务本身作为全局唯一实体，工作区、联通块、Todo、草稿和时间轴中的节点只保存对任务 ID 的引用。同一个任务可以同时出现在多个规划场景中，但始终指向同一份数据：

- 在任意视图修改标题、状态、时间或颜色，其他引用位置同步更新
- 一个任务可同时归属于多个联通块，无需重复创建
- Todo 和甘特读取同一任务数据，规划层与执行层自然联动
- 删除、完成、排期等状态只维护一次，避免多份副本逐渐失真

这使 Planner 的节点复用不是视觉上的“复制粘贴”，而是数据层面的真正全局引用。

### 2. 独创的增强型甘特

Planner 的时间轴不只是静态展示工期，而是与任务图谱、树形层级和周期时间模板共同工作的交互式排期层：

- 图谱节点与甘特任务条共享全局任务数据，修改结果双向一致
- 支持分钟、小时、天三种时间精度，兼顾短时任务和长期计划
- 可直接拖动任务条两端，调整开始与结束时间
- 按树形任务关系缩进展示，并支持展开或折叠子任务
- 支持拖拽调整任务顺序、显示或隐藏已完成任务、快速回到当前时间
- 将日 / 周时间模板作为背景带叠加到甘特中，同时观察任务排期与固定作息
- 显示任务预计耗时、完成状态和剩余时间，使排期具备即时执行反馈

相比只强调“项目—工期”的传统甘特，Planner 的增强型甘特同时表达任务层级、时间粒度、周期资源和实时状态。

### 3. 用树形关系替代文件夹层级

传统文件夹要求一个任务只能被放进某个固定路径，层级越深，信息越容易被隐藏和割裂。Planner 使用可展开的树形结构与任务关系图表达层级：

- 父任务与子任务的关系直接可见，不必逐层打开文件夹查找
- 同一个全局任务可以被多个规划结构引用，不受单一文件夹归属限制
- 层级结构、依赖关系和执行顺序可以同时表达
- Todo 与甘特沿用同一棵任务树，减少不同页面之间的认知切换

这种设计保留了文件夹的层级组织能力，同时解决了任务只能“存放在一个位置”的限制。

### 4. 无账号、文件驱动、本地优先

Planner 不建立用户账户体系，也不要求把个人目标、日程和任务上传到业务服务器。应用打开后即可使用，数据在日常操作中自动保存在当前浏览器；需要备份、更换设备或迁移环境时，再通过 JSON 文件主动导出和导入。

- **无需登录：**没有注册、验证码、账户绑定和订阅流程
- **本地保存：**核心规划数据默认写入浏览器 `localStorage`，不依赖远程数据库
- **文件迁移：**用户可以将结构化数据导出为 JSON，并在另一台设备或浏览器中导入
- **数据自主：**是否保存、复制、传输和删除备份文件由用户决定
- **隐私友好：**个人目标与任务默认无需离开本地浏览器
- **部署简单：**纯前端静态构建，无需搭建登录、鉴权、数据库或业务后端

这种方式不同于依赖云端账号自动同步的 SaaS 工具。Planner 用“浏览器本地数据 + 用户主动管理的备份文件”换取更低的使用门槛、更清晰的数据归属和更简单的部署方式。

> 隐私边界：Planner 默认不上传规划数据，但数据安全仍依赖用户设备、浏览器环境和备份文件的保管。使用公共电脑前应导出所需数据并清理站点数据；JSON 备份目前未加密，不应随意发送给他人。

### 与具体产品的逐一对比

#### Planner vs Notion

Notion 的优势是文档、Wiki 和数据库高度自由。用户可以为同一个数据库建立表格、看板、日历和时间线等关联视图，因此它也能实现“同一条记录在多个视图中同步”。不过，这种能力主要建立在数据库配置之上，任务依赖、树形执行路线和图谱关系通常需要通过 Relation、Sub-item、模板或第三方方案组合完成。

Planner 则把全局引用直接设计成默认任务模型：画布、联通块、Todo、草稿与甘特中的节点天然指向同一任务，不需要用户先设计数据库。其重点不是搭建知识库，而是直接表达任务的层级、依赖、归属和时间。

| 对比点 | Notion 的典型做法 | Planner 的做法 |
| --- | --- | --- |
| 同一任务复用 | 同一数据库记录可显示在多个关联视图 | 所有任务节点默认引用全局唯一任务实体 |
| 任务组织 | 页面层级、数据库属性、筛选与 Relation | 树形父子关系、DAG 依赖和联通块多重归属 |
| 甘特能力 | 数据库时间线，适合按日期查看记录 | 分钟 / 小时 / 天级甘特，与任务树和周期模板联动 |
| 使用门槛 | 灵活，但复杂工作流需要自行搭建数据库 | 打开即可按照既定规划模型创建任务关系 |
| Planner 的差异 | — | 将 Notion 需要配置的关系能力做成原生规划交互 |

#### Planner vs 滴答清单 / Todoist

滴答清单和 Todoist 擅长快速收集任务、日期提醒、重复任务、日历和移动端执行，是成熟的个人效率工具。它们通常通过项目、清单、标签、过滤器和子任务组织内容，核心问题是“今天应该完成什么”。

Planner 更关注执行之前的复杂规划问题：一个目标应如何拆解、任务之间为什么存在先后关系、同一任务属于哪些目标、固定作息下怎样排进时间。任务确认后，再进入 Todo 执行路线。

| 对比点 | 滴答清单 / Todoist 的典型做法 | Planner 的做法 |
| --- | --- | --- |
| 核心入口 | 快速录入清单、日期、提醒和重复规则 | 在可视化图谱中拆解目标并建立依赖 |
| 层级 | 项目、清单和缩进子任务 | 可拖拽的树形执行路线，并同步到增强甘特 |
| 多重归属 | 常通过标签、筛选器或智能清单查看 | 同一个全局任务可直接归属多个联通块 |
| 依赖表达 | 主要强调优先级与日期，任务依赖不是核心画布 | 用 DAG 有向连线直接表达前置关系 |
| Planner 的差异 | — | 从“记录待办”向前延伸到“构建任务系统” |
| Planner 当前不足 | — | 暂无成熟的提醒、自然语言录入和原生移动端能力 |

#### Planner vs Trello

Trello 以看板、列表和卡片表达工作状态，优势是直观的流程流转与团队协作。卡片通常从“待处理”移动到“进行中”和“已完成”，非常适合回答“任务目前处于哪个阶段”。

Planner 的画布不以状态列作为空间结构，而是用节点位置和有向边显示任务之间的真实关系；联通块也不是封闭看板，同一任务可被多个联通块引用。

| 对比点 | Trello 的典型做法 | Planner 的做法 |
| --- | --- | --- |
| 可视化对象 | 看板中的列表与卡片 | 无限画布中的任务节点、根节点与依赖边 |
| 主要关系 | 卡片所在状态列和排列顺序 | 父子层级、前后置依赖、联通块归属和排期 |
| 跨项目复用 | 常通过移动、复制、镜像、链接或自动化组织 | 节点直接引用同一全局任务，可属于多个联通块 |
| 时间管理 | 日期、日历或时间线能力 | 与图谱同源的增强甘特及日 / 周模板背景 |
| Planner 的差异 | — | 从“状态流看板”转向“关系网络 + 时间执行” |
| Planner 当前不足 | — | 暂无 Trello 成熟的多人协作、评论、权限和自动化生态 |

#### Planner vs XMind

XMind 擅长自由发散、树状拆解和演示，是构思阶段非常成熟的思维导图工具。它的主题节点主要服务于知识表达；将主题复制到另一张导图后，通常成为新的独立内容，任务状态和排期也不是其核心执行模型。

Planner 保留了画布拆解和树形思考的直观性，但节点背后是可执行的全局任务，拥有状态、耗时、起止时间、Todo 归属和甘特排期。

| 对比点 | XMind 的典型做法 | Planner 的做法 |
| --- | --- | --- |
| 节点本质 | 当前导图中的主题内容 | 带状态与时间属性的全局任务实体引用 |
| 关系表达 | 主题树、概要、边界与联系线 | 树形层级、DAG 依赖和跨联通块连接 |
| 跨图复用 | 通常复制主题形成另一份内容 | 多个规划场景引用同一任务并同步修改 |
| 落地执行 | 以思考、整理和展示为主 | 可直接进入 Todo 路线和甘特排期 |
| Planner 的差异 | — | 让思维节点从“信息”变成可追踪、可排期的任务 |
| Planner 当前不足 | — | 暂无 XMind 丰富的导图结构、主题样式和演示能力 |

#### Planner vs Microsoft Project

Microsoft Project 是专业项目管理工具，擅长 WBS、甘特图、前后置依赖、关键路径、资源分配、成本和基线管理，适用于工程项目和组织级计划。它的任务通常归属于具体项目和 WBS 结构，操作逻辑偏专业项目经理。

Planner 不与其竞争大型工程管理能力，而是把图谱关系、个人作息和执行清单结合起来，为个人学习、毕业设计、创作和长期成长目标提供更轻量的规划方式。

| 对比点 | Microsoft Project 的典型做法 | Planner 的做法 |
| --- | --- | --- |
| 目标用户 | 项目经理、工程和组织项目 | 管理复杂目标的个人用户 |
| 任务结构 | WBS 任务表、摘要任务和里程碑 | 全局任务、树形路线、DAG 和联通块 |
| 甘特重点 | 工期、关键路径、资源、成本与基线 | 多时间精度、个人周期模板、剩余时间与图谱联动 |
| 任务复用 | 主要围绕具体项目计划组织 | 同一任务可跨多个目标场景引用 |
| Planner 的差异 | — | 将专业甘特简化为个人可操作的“关系 + 作息 + 执行”时间层 |
| Planner 当前不足 | — | 暂无关键路径、资源平衡、成本和基线等专业能力 |

#### Planner vs Obsidian

Obsidian 通过双向链接和关系图谱连接笔记，具有本地优先、文件可控和插件生态丰富等优势。它解决的是知识之间如何关联，而任务管理通常依赖 Markdown 语法、属性、查询和社区插件。

Planner 与 Obsidian 都强调关联和本地数据，但 Planner 中的关系不是笔记链接，而是具有明确执行语义的任务关系：节点包含完成状态、预计耗时、起止时间和所属联通块，边可以表达任务依赖，并直接驱动 Todo 与甘特。

| 对比点 | Obsidian 的典型做法 | Planner 的做法 |
| --- | --- | --- |
| 全局对象 | Markdown 笔记文件与块链接 | 结构化全局任务实体 |
| 图谱语义 | 展示笔记之间的引用与知识关联 | 表达任务依赖、层级和规划归属 |
| 时间执行 | 通常使用属性、查询或任务插件 | 原生 Todo 路线、任务状态和增强甘特 |
| 本地数据 | 本地 Markdown 文件，可自由管理 | 浏览器本地存储，可导出 / 导入 JSON |
| Planner 的差异 | — | 图中的每条关系都面向任务规划和执行，而非泛知识链接 |
| Planner 当前不足 | — | 暂无 Obsidian 的文件级开放性、Markdown 编辑和插件生态 |

#### Planner vs 云端账号型规划软件

Notion、Trello、Todoist、滴答清单等产品通常以账号和云端工作区为中心。这样做的优势是跨设备自动同步、团队协作和统一运维，但用户必须接受平台的账户体系、网络依赖和数据存储方式。

Planner 选择另一条路线：不提供登录入口，不维护用户表和远程业务数据库。用户直接使用应用，核心数据保存在浏览器，需要迁移时导出一个 JSON 文件，再在目标环境中导入。

| 对比点 | 云端账号型软件 | Planner |
| --- | --- | --- |
| 开始使用 | 注册 / 登录后创建云端空间 | 打开网页即可使用 |
| 默认存储位置 | 服务商云端数据库 | 当前浏览器本地存储 |
| 跨设备方式 | 登录同一账号自动同步 | 用户主动导出并导入 JSON 文件 |
| 数据控制 | 受平台账户、服务条款和导出能力影响 | 备份文件由用户自行保存、复制和删除 |
| 隐私模式 | 数据通常需要上传以提供同步与协作 | 规划数据默认无需上传业务服务器 |
| 部署组成 | 前端、后端、数据库、鉴权及运维 | Vite 构建后的静态文件 |
| 适用场景 | 团队协作、实时同步、多端提醒 | 个人规划、隐私优先、轻量部署和离线式迁移 |

两种模式并非绝对优劣：云端账号模式更适合协作和无感同步，Planner 的文件驱动模式则更适合重视隐私、数据自主和部署成本的个人用户。

### 竞品分析结论

- Notion 证明了“同一记录多视图”有价值，但 Planner 将其从数据库配置转化为默认的任务引用模型。
- 滴答清单和 Todoist 擅长提醒用户执行，Planner 重点解决执行前的目标拆解与依赖规划。
- Trello 擅长表示任务状态流转，Planner 擅长表示任务之间的结构与时间关系。
- XMind 擅长把想法画出来，Planner 继续让这些节点进入排期和执行。
- Microsoft Project 擅长组织级工程排期，Planner 将部分甘特思想转化为个人可用的增强时间层。
- Obsidian 擅长连接知识，Planner 则连接可以被完成、排期和复用的任务。
- 云端账号型产品用账户换取自动同步与协作，Planner 用本地保存和备份文件换取数据自主、隐私与轻量部署。

因此，Planner 的创新不在于声称市场上完全没有任务、树形结构或甘特图，而在于把这些已有能力用**全局任务引用**连接起来，形成统一的数据模型和连续的个人规划工作流。

### Planner 的市场定位

Planner 并不试图替代大型团队协作平台或专业工程项目管理软件，而是聚焦于一个更具体的空缺：**为个人复杂目标提供既能自由构思，又能严谨表达依赖和排期，还能直接进入日常执行的统一工具。**

其差异化可以概括为：

> **一个全局任务数据源 + 多个引用场景 + 树形层级与 DAG 依赖 + 增强型甘特 + Todo 执行闭环 + 无账号的文件驱动数据模式**

| Planner 的差异点 | 带来的价值 |
| --- | --- |
| 全局引用，而非复制节点 | 避免同一任务在多个计划中产生数据副本和状态冲突 |
| 树形关系，而非固定文件夹 | 父子层级直接可见，同时允许任务被多个规划结构复用 |
| 联通块，而非单一项目归属 | 可从不同目标或主题切入查看同一个任务网络 |
| 增强甘特，而非独立时间表 | 依赖、层级、排期、作息模板和完成状态集中呈现 |
| 多视图共享任务实体 | 从草稿、规划、排期到 Todo 执行无需重复录入和同步 |
| 无账号、文件驱动 | 个人数据默认留在浏览器，通过用户持有的 JSON 文件完成迁移 |
| 纯静态部署 | 无需建设账户、鉴权、数据库和业务服务器，降低搭建与维护成本 |

### 亮点实现拆解：别人怎么做，Planner 怎么做

下面进一步从具体机制说明差异。“市场常见实现”指同类产品的典型原生工作流，并不否认个别产品可通过付费版本、插件、关联数据库或自动化实现相近效果。

| 亮点 | 市场上有没有、通常怎么做 | Planner 有没有、具体怎么做 | 实际价值 |
| --- | --- | --- | --- |
| 全局任务引用 | **部分有。**数据库型工具可以让多个视图显示同一条记录；清单、看板和脑图工具跨项目使用时则常依赖复制、镜像卡片或手动关联 | **有，且是底层设计。**任务集中存储为全局实体，画布节点只保存 `taskId`；联通块、Todo、草稿、甘特都引用同一任务 | 从构思到执行始终维护一份真实数据，避免副本冲突 |
| 跨规划多重归属 | **部分有。**常用标签、筛选、数据库关系或快捷方式模拟，一个任务仍往往有主要项目或固定路径 | **有。**任务保存多个 `componentIds`，同一节点可直接加入多个联通块，并在不同筛选组合中出现 | 一个任务可同时服务多个目标，适合现实中交叉复用的复杂任务 |
| 树形结构替代文件夹 | **有相近能力。**Todoist、Project 等提供子任务或 WBS；Notion 等主要以页面层级收纳；XMind 擅长主题树但执行属性较弱 | **有，并与执行数据统一。**父子关系不被藏在文件夹路径里，而是直接呈现在 Todo 路线和甘特左侧任务树中，可展开、折叠和重排 | 查找路径变成理解关系，层级信息始终可见 |
| DAG 依赖图 | **专业项目工具有。**通常以任务表的前后置字段或甘特箭头呈现；脑图有连线，但通常不承担任务执行状态 | **有。**通过 React Flow 节点与有向边表达依赖，支持画布拖动、缩放、框选、跨联通块连线和双击删边 | 复杂任务的先后约束从字段变为直观拓扑 |
| 联通块 | **少见同构设计。**常见工具更多使用项目、空间、看板或标签，它们通常是容器或筛选条件 | **有。**每个联通块既是可筛选的任务集合，也有可连线根节点和独立视觉属性；节点可以属于多个联通块 | 既保留“项目视角”，又不把任务锁死在单一容器中 |
| 增强型甘特 | **有。**Microsoft Project 等专业工具的甘特与关键路径、资源管理很强；轻量工具通常只提供天级时间线 | **有，面向个人任务进一步联动。**支持分钟、小时、天精度，任务树展开折叠、顺序拖拽、两端缩放、当前时间线、剩余时间和完成状态 | 既能做长期规划，也能处理小时甚至分钟级个人排期 |
| 周期模板叠加甘特 | **有相近概念。**专业工具提供工作日历，清单工具提供重复任务，但通常不把个人作息直接可视化叠加在任务甘特背景 | **有。**用户可制作 24 小时 / 周模板，时间块按周期投影为甘特背景色带 | 排任务时能直接看到睡眠、课程、工作等固定时段，减少时间冲突 |
| 图谱—甘特联动 | **部分有。**专业项目工具以任务表和甘特联动；白板 / 脑图与排期常是两个模块或两套数据 | **有。**拓扑节点与甘特条引用同一任务，标题、状态、耗时和起止时间天然一致 | 空间关系和时间关系成为同一计划的两个观察维度 |
| 规划—Todo 闭环 | **普遍有部分能力。**很多工具能将项目任务放入“今日”或看板，但构思图、依赖图与执行清单常相互独立 | **有。**画布节点可单个或批量加入 Todo；Todo 继续引用原任务，并可拖成多条执行分线和父子路线 | 无需把“规划中的任务”再抄一遍成为待办事项 |
| Todo 树形执行路线 | **有列表、看板和子任务。**大多按日期、优先级、状态列或缩进列表组织 | **有独立表达。**Todo 以多分线树形路线显示，拖到节点上即可成为子任务，也可跨分线和调整前后顺序 | 不只回答“做什么”，还表达“沿哪条路线、按什么关系做” |
| 草稿到任务连续性 | **白板型产品有。**但白板便签转项目任务有时需要转换、复制或额外关联 | **有。**草稿画布中的节点直接创建并引用全局任务，可连线、手绘、框选；后续视图继续使用同一实体 | 灵感不需要二次录入，降低从发散思考到结构化规划的损耗 |
| 批量语义操作 | **普遍支持部分批量编辑。**通常在列表勾选后修改字段或移动项目 | **有。**画布框选多个节点后，可一次完成 / 恢复、加入 Todo、设置多重归属、统一颜色或从当前画布移除 | 批量操作作用于图谱上下文，而不仅是表格行 |
| 可配置视觉编码 | **普遍有颜色、标签或主题。**但依赖线的含义和样式通常固定 | **有。**任务可自定义节点色与文字色；联通块可独立设置根节点、统一节点、连线颜色以及曲线 / 折线 / 直线 | 用颜色和线型编码不同计划语义，提高大图可读性 |
| 全局撤销 / 重做 | **桌面软件和白板常见，网页任务工具的覆盖范围各异。**跨多个模块的连续操作未必进入同一历史 | **有。**Zustand 状态层保存历史快照；拖动、批量修改等连续动作会分组为一次历史记录，并持久化恢复结果 | 对复杂画布和批量编辑更安全，不必担心一次误操作破坏规划 |
| 本地优先 | **多数协作产品以云端账号为中心。**优点是多人协作与同步，但离线、自主迁移和隐私取决于产品方案 | **有。**纯前端运行，无需账号和后端，状态自动保存在浏览器 `localStorage` | 部署轻、启动快，个人数据默认不需要上传服务器 |
| 数据可迁移 | **多数产品提供不同程度的导出。**格式和可恢复范围由平台决定 | **有。**提供带格式与版本校验的 JSON 导出 / 导入，限制异常大文件，并在覆盖前二次确认 | 不依赖某台设备，可主动备份和恢复核心结构化规划数据 |
| 文件驱动使用 | **部分桌面软件以文件为中心；多数 Web 规划工具以账号和云端工作区为中心。** | **有。**无需登录，浏览器负责日常持久化，JSON 文件负责备份和环境间迁移 | 用户掌握数据副本，不依赖账户是否可用或云服务是否持续运营 |
| 轻量部署 | **云端协作产品通常需要后端、数据库、鉴权和运维。** | **有。**生产构建仅生成静态资源，可部署到 GitHub Pages 等静态托管平台 | 毕设展示和个人搭建成本低，发布流程简单 |
| 自定义任务状态 | **大部分项目管理软件有，简单清单工具相对固定。** | **有。**除系统状态外，可新增、重命名和删除个人状态，完成状态仍统一驱动各视图 | 能适配学习、创作、研发等不同工作流，而不被固定流程限制 |

### 能力边界

Planner 当前的优势集中在个人复杂目标的结构化表达与跨视图一致性，而不是覆盖所有市场需求：

- 相比 Microsoft Project，暂未覆盖资源成本、基线、关键路径等大型项目管理能力。
- 相比 Trello、Notion 等团队平台，暂未提供多人实时协作、评论、权限与云端同步。
- 相比 Todoist 等成熟清单工具，暂未覆盖自然语言录入、跨平台提醒和移动端原生应用。
- 当前数据以浏览器本地存储为主，跨设备使用需手动导出 / 导入 JSON；草稿自由画笔笔迹目前不随 JSON 备份迁移。

这些边界也说明了 Planner 的取舍：将实现重点放在**任务全局引用、图结构组织、树形层级和增强甘特的一体化**，而不是复刻已有软件的全部功能。

## 功能亮点

### 1. DAG 可视化任务规划

- 在无限画布中创建、拖动和缩放任务节点
- 使用有向连线表达任务的前置关系与执行顺序
- 支持跨计划连接，将分散目标整合为统一任务网络
- 支持框选和批量操作，降低复杂计划的维护成本

### 2. 可复用的“联通块”组织方式

- 将一组相互关联的任务组织为独立联通块
- 同一个任务节点可归属于多个联通块，减少重复录入
- 可按联通块筛选工作区，并分别设置节点颜色、连线颜色与连线形状

### 3. 图谱与时间轴双视图联动

- 工作区下方提供连续时间轴，直观展示任务排期
- 支持分钟、小时和天级精度切换
- 可拖动任务时间条及两端控制点，快速调整开始时间与结束时间
- 支持调整任务显示顺序，兼顾依赖关系与时间安排

### 4. Todo 执行路线

- 将规划图中的任务一键加入 Todo
- 支持创建多条执行分线
- 通过拖拽调整顺序、切换分线或建立父子任务关系
- 可直接标记任务完成状态，让规划结果落到日常执行

### 5. 自由草稿画布

- 创建多个独立草稿，用于早期构思和快速整理
- 支持节点、连线、自由画笔、橡皮擦、框选与画布移动
- 草稿节点与全局任务数据保持关联，便于从灵感逐步形成正式计划

### 6. 日 / 周时间模板

- 创建 24 小时时间模板或一周周期模板
- 通过拖动和缩放时间块规划固定作息、学习或工作时段
- 支持自定义时间块名称与颜色，并将选中的模板应用到工作区

### 7. 本地优先与数据安全

- 数据自动持久化到浏览器 `localStorage`
- 支持撤销与重做，也支持 `Ctrl/Cmd + Z`、`Ctrl/Cmd + Shift + Z` 快捷键
- 可将核心结构化数据导出为 JSON 文件，并在其他设备或浏览器中导入恢复
- 无需后端服务和 API Key，开箱即用

## 使用方法

### 快速开始

1. 打开 [Planner 在线版](https://panxixii.github.io/Planner/)。
2. 点击欢迎页中的“开始使用”。
3. 在“工作区”顶部新建联通块，并在画布中建立任务节点和依赖连线。
4. 点击任务节点可编辑标题；双击节点可打开更多操作，设置详情、归属联通块或加入 Todo。
5. 展开底部时间轴，为任务安排开始与结束时间。
6. 前往左侧的 Todo、草稿或时间模板页面，继续完善执行路线和时间规划。

### 主要页面

| 页面 | 用途 |
| --- | --- |
| 工作区 | 创建任务关系图、管理联通块、设置任务详情并进行时间排期 |
| Todo | 按主线 / 分线组织待办任务，通过拖拽建立执行顺序和父子关系 |
| 草稿 | 使用节点、连线和自由绘制进行头脑风暴 |
| 时间模板 | 创建可重复使用的日计划与周计划背景 |

### 数据备份

- 点击工作区右上角的“导出数据”，下载核心结构化数据的 JSON 备份。
- 点击“导入数据”并选择 Planner 导出的 JSON 文件，即可恢复数据。
- 导入会覆盖当前浏览器中的 Planner 数据，操作前建议先导出备份。
- “清空计划”会清除当前工作区中的自定义计划与任务，请谨慎操作。

> 数据保存在当前浏览器中。清除浏览器站点数据、使用无痕模式或更换设备时，原数据不会自动同步，请及时导出备份。

> 当前 JSON 备份不包含草稿中的自由画笔笔迹；任务节点、连线、联通块、Todo、时间模板等结构化数据可正常备份。

### 数据与隐私说明

- Planner 没有登录系统，不会创建云端用户账户。
- 任务、联通块、Todo、时间模板等数据默认只保存在当前浏览器中。
- 更换浏览器、清除站点数据或更换设备前，需要手动导出 JSON 备份。
- 导出的 JSON 文件未加密，其中可能包含任务标题、描述和日程，请妥善保管。
- 若将项目部署到自己的静态站点，不需要额外配置数据库、鉴权服务或 API Key。

## 本地启动

### 环境要求

- [Node.js](https://nodejs.org/) 18 或更高版本
- npm（随 Node.js 一同安装）

### 启动步骤

```bash
# 1. 克隆项目
git clone https://github.com/panxixii/Planner.git

# 2. 进入项目目录
cd Planner

# 3. 安装依赖
npm install

# 4. 启动开发服务器
npm run dev
```

启动成功后访问：**http://localhost:3000/**

本项目当前无需配置环境变量或第三方 API Key。

### 构建与预览

```bash
# TypeScript 类型检查
npm run lint

# 构建生产版本，产物位于 dist 目录
npm run build

# 本地预览生产构建
npm run preview
```

### 部署方式

Planner 构建后是纯静态网站，可部署到 GitHub Pages、Vercel、Netlify、对象存储或任意静态 Web 服务器：

```bash
npm install
npm run build
```

将生成的 `dist/` 目录发布即可。项目使用相对资源路径，适合部署到 GitHub Pages 的仓库子路径；不需要部署 Node.js 服务、数据库或登录鉴权模块。
